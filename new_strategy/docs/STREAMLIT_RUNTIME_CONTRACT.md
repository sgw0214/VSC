# Streamlit Runtime Contract

이 문서는 대시보드, 텔레그램, 가격기준맵, 의사결정표가 같은 계약을 따르도록 강제하는 운영 계약입니다.
반복 실수는 대부분 "한 곳만 고치고 같은 값을 읽는 다른 서비스까지 확인하지 않은 것"에서 발생했습니다.
앞으로는 아래 계약을 통과하기 전에는 수정 완료로 선언하지 않습니다.

## 1. 단일 출력 경로 계약

- 운영 출력물은 반드시 `strategy_output_path()` 기준 로컬 운영 출력 경로만 사용합니다.
- 같은 이름의 런타임 파일이 repo-local `output/strategy_v2`에도 있으면 shadow runtime으로 간주하고 실패 처리합니다.
- 같은 파일명이 여러 경로에 있으면 어느 파일이 진짜 운영 파일인지 먼저 확인합니다.

## 2. 단일 진실원천 계약

- 의사결정표, 상세 패널, 가격기준맵, 실행 가이드는 같은 `signal_df` 최종 row를 사용해야 합니다.
- `display_signal`, `display_signal_ko`, `v2_contract_mode`, `v2_buy_ma`, `v2_sell_ma`는 모든 서비스에서 동일해야 합니다.
- 오프라인 함수 결과와 브라우저 화면 결과가 다르면 서버 stale 또는 잘못된 진실원천 사용으로 판단합니다.

## 3. 보유 종목 계약 이평가 계약

- 보유 종목의 가격기준맵은 `v2_buy_ma`, `v2_sell_ma`를 직접 기준값으로 사용합니다.
- 가격기준맵의 `매수이평가`, `매도이평가`는 같은 row의 `v2_buy_ma`, `v2_sell_ma`와 정확히 일치해야 합니다.
- 손절가는 같은 계약 이평가 기준에서 계산되어야 합니다.
- 오래된 industry snapshot, stale snapshot, 다른 계산 경로를 앞세우면 실패입니다.

## 4. 상세 종목 선택 계약

- 의사결정표와 상세 패널은 서로 다른 UI 영역입니다.
- 상세 패널을 해석하기 전에는 현재 `selected_code`가 무엇인지 먼저 확인합니다.
- 선택된 종목이 아닌 다른 종목의 화면을 근거로 상세 패널 값을 해석하면 실패입니다.

## 5. 서버 stale 계약

- 코드 또는 출력 파일이 정상이어도 실행 중인 Streamlit 프로세스가 예전 코드/캐시를 물고 있을 수 있습니다.
- 파일, Python payload, 브라우저 화면 3단계가 모두 일치할 때만 정상으로 봅니다.
- 서버가 stale이면 "코드가 맞다"고 완료 선언하지 않습니다.
- `run_streamlit_dashboard.ps1` wrapper는 실행 중에도 `new_strategy` Python 소스 변경을 감지하면 Streamlit child를 자동 재기동해야 합니다.
- `server_on.bat` 실행 시 이미 떠 있는 서버라도 source token이 달라졌으면 기존 인스턴스를 stale로 보고 재기동해야 합니다.
- F5 캐시 재로딩은 파일 데이터 stale을 해결하는 계약이지, 오래된 서버 코드 자체를 교체하는 계약이 아닙니다.

## 6. 수정 완료 선언 계약

- 아래 3단계를 모두 통과하기 전에는 "수정 완료"라고 말하지 않습니다.
  1. 원본 출력 파일 확인
  2. Python 함수/payload 확인
  3. 실제 브라우저 화면 확인
- 한 서비스만 맞고 다른 서비스가 다르면 미완료입니다.
- 사용자 피드백을 최종 검증으로 떠넘기지 않습니다. 최종 확인 책임은 Codex가 가집니다.

## 7. 이번에 반복된 실수 기록

- 출력 파일은 2026-04-17로 갱신됐는데, Streamlit 프로세스는 2026-04-15에 실행된 상태로 남아 있었습니다.
- 그래서 F5 재로딩 코드와 NA 처리 수정이 서버에 적용되지 않았고, 새로고침해도 날짜가 계속 오래된 값으로 보였습니다.
- 파일만 맞는지 확인하고 브라우저 화면까지 확인하지 않으면 같은 문제가 반복됩니다.
- 코드 변경 후 서버 소스 token이 바뀌었는지, 실제 서버가 새 token으로 떠 있는지 확인해야 합니다.

## 8. 다시 반복하지 않기 위한 실행 순서

- 수정 후 같은 값을 읽는 파일, 함수, UI 서비스를 모두 나열합니다.
- 수정 중 경로 계약과 진실원천 계약을 깨지 않는 방식으로만 바꿉니다.
- 수정 후 파일 -> payload -> 브라우저 화면 순서로 직접 확인합니다.
- 최종 보고는 원인 / 조치 / 결과만 짧게 정리하고, 검증이 끝난 상태에서만 보고합니다.
